# Observation-led research closed loop

Turn observed behavior into a testable problem, then connect problem → competing explanations → method design → evidence → revision. This is primarily an empirical and engineering research workflow; do not impose an observation-first origin on theoretical, exploratory, or explicitly hypothesis-driven work.

## Select the current decision

Read the user's observations, logs, methods, results, and directly relevant project records, not unrelated projects. If information is missing, offer a provisional assessment and the cheapest useful evidence to collect. Do not invent data or begin with an exhaustive questionnaire.

If only a topic is available, use problem localization to define a provisional task, operational measures, lawful data preparation, and a minimal observation plan. Keep the pain point, mechanism, and novelty unverified. Lack of data or browsing is not a reason to refuse a useful starting plan.

Load only the stages relevant to the current request:

| Need | Stage | Deliverable |
|---|---|---|
| An unclear anomaly | [Problem localization](../research-problem-localization/SKILL.md) | Quantified problem with denominators, boundaries, and impact |
| Uncertain cause | [Bottleneck diagnosis](../research-bottleneck-diagnosis/SKILL.md) | Competing explanations and discriminating tests |
| Prior methods and novelty | [Gap mapping](../research-gap-mapping/SKILL.md) | Claim–source–conditions–gap map |
| A mechanism needs a cheap test | [Minimal prototype](../research-minimal-prototype/SKILL.md) | Small informative test and continue/revise/stop criteria |
| A promising pilot needs stronger evidence | [Validation design](../research-validation-design/SKILL.md) | Fair comparisons, independent evaluation, ablations, and limits |
| Directions compete for resources | [Portfolio management](../research-portfolio-management/SKILL.md) | Main line, backups, budgets, and switch decisions |

Stages can overlap and loop back. Literature can refine a problem; a failed prototype can return to measurement or diagnosis; failed validation can require a narrower claim, a different mechanism, or stopping—not automatic module additions.

## Shared invariants

- Separate observations, replicated results, inferences, hypotheses, and literature reports. Unmeasured values remain unknown; illustrative 80%/32×32 figures are not project results.
- An ablation supports contribution under a specified configuration and protocol, not automatic real-world causal identification. Multiple datasets support tested scopes, not universal generalization.
- Finding a paper does not establish claim support. Failure to find prior work does not establish novelty. Without live search, provide a clearly pending search plan.
- Planning is not permission to execute. Explanation, diagnosis, or design does not authorize code changes, training, paid calls, remote jobs, or additional agents. Actual execution follows the current user scope and budget, with bounded retries.
- These are research skills, not competition award templates, marketing workflows, or language-learning standards. Classification and routing are not a security sandbox.
- Reuse existing project records. When the user needs saved artifacts, adapt the [project state template](assets/research-state.md); do not require all fields, duplicate directories, or automatic file creation.

## Close the loop

Deliver what the current task needs, including what is supported and unsupported, the most important uncertainty, the next action likely to change the decision, and the evidence that would reverse it. For full-loop requests, add dependencies, budget limits, and return points. Do not promise publication or performance gains.

For proportions, ablations, and failure interpretation, read [decision boundaries](references/decision-boundaries.md) as needed. For methodological provenance, read [method sources](references/method-sources.md). No external skill, MCP server, paid model, or Python package is required by these instructions. Use available tools for real calculation and search, and report limitations honestly.
