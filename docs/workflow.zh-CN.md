# 科研闭环完整流程与作用

[English](workflow.md) · [首页](../README.zh-CN.md)

## 底层逻辑

形成一条可追溯的链：**观测到的问题 → 竞争解释 → 方法操作/干预 → 机制预测 → 实验证据 → 有边界的结论 → 下一项决策**。

它不是要求先证明所有原因才能思考，也不是所有理论研究的统一模式。作用是避免“先造模型再凑问题”、事后包装机制和无上限试验。研究计划始终不等于执行授权。

根据已有证据选择入口：只有主题时先定义任务、准备合法数据与测量，痛点保持未知；已有完整结果时直接审计证据，不为走流程而重做前面的阶段。

## 1. 从真实现象定位可量化问题

**输入：**复现差异、部署故障、实验异常、定性观察，或需要启动测量的主题。

**操作：**明确任务、指标、单位、阈值、分子/分母、采样单位、系统版本和实际代价。按相关边界分层，同时保留总体结果；先检查标签、统计脚本、缺失、预处理和管线，而不是直接判为算法缺陷。

**产物：**问题卡，说明差距出现/不出现的条件、大小与不确定性、原始来源和待测内容。

**继续条件：**差距在当前问题下足够可信且重要，进入归因。否则修测量、补数据、重新定义任务或停止。

**示例：**小目标 1,000 个漏 80，大目标 100 个漏 20，漏检率是 8% 与 20%。小目标贡献 80% 的漏检，却不具有最高组内风险。减少总错误、降低高风险组错误和减少业务损失是不同目标。数字仅为演示，不是项目结果。

## 2. 归因分析与瓶颈验证

**输入：**已量化的问题及边界、相关系统结构和日志。

**操作：**提出可信竞争解释、可观察预测和反证结果；选择最便宜且能区分解释的控制、干预、删除、替换或交互实验。追踪同时变化的容量、计算、训练量和优化因素。

**产物：**假说矩阵、优先测试、控制条件、成本、解释范围和能推翻假说的结果。

**继续条件：**证据指向可操作瓶颈后，形成针对机制的设计约束。尚未区分时做下一项高信息量测试，或缩小结论，不需要先穷尽所有可能原因。

**失败解释：**干预没生效；生效但机制预测被可靠证据反驳；中介变了但下游无收益；最终分数提高但中介未建立——这四种情况不能混为一谈。宽区间同时包含零与预期变化时，应标为未区分；有效测量排除了预期变化，才是相关反证。

**示例：**去掉 A 后低两分，同时参数少 40%、训练时间减半，最多支持该协议下的贡献，不能证明 A 的独特机制是根因。需考虑预算匹配、简单替代和机制中介测量。

## 3. 文献调研与 gap 定位

**输入：**具体任务、瓶颈假说、现实约束和候选操作。

**操作：**用任务、机制、约束、同义词和相反结果检索一手论文及官方补充材料。近期工作优先，但保留奠基工作与最接近前作；记录日期、覆盖和访问限制。每个主张要定位到来源、假设、数据/协议、结果和成本，区分作者报告与本方推断。

**产物：**主张—来源—条件矩阵，前作已解决部分、已证实限制与未评估维度，以及暂定 gap 和方法的本质差别。

**继续条件：**已有方法满足需求，就优先复现或使用；否则将设计差异写成可检验操作，列出假设、代价和反例。访问不足时创新保持待核实，不编造引文。

**gap 表达：**“在 X 条件下，已有方法存在 Y 代价或缺少 Z 证据；操作 M 相较最接近方法 N 的区别是 D，预测 O，代价为 R。”创新不一定推翻前人，也可以有证据地补齐忽略的维度。

## 4. 最小原型与低成本试错

**输入：**具体操作、机制预测、竞争解释、开发数据和资源约束。

**操作：**选择能区分假说的最低成本形式：推导、反例、测量复核、玩具研究或小实现。保留触发瓶颈的条件，加入可信简单/已有基线，按需测瓶颈、中介、结果和成本。在看结果前写继续/修订/停止条件。

**产物：**原型计划，包含输入、协议、资源及估时依据、迭代上限、结果解释和后续独立确认路线。

**继续条件：**有价值的信号可进入完整验证；重要机制疑问也可继续聚焦验证。有效负结果可以止损或转向。玩具数据提升不是完整优越性证据。

**预算规则：**不知道耗时就写预算分配，不编造预计时长。实际执行获准后，利用既有日志或受上限约束的小批运行估时；总预算计入准备、分析和故障缓冲。必要验证放不下，就降级为明确标注的试点、寻找更便宜证据或停止，不截断后假称验证完成。

**示例：**VLM 提示减少了无图像依据的对象断言，还需检查正确对象覆盖和拒答。少说内容可能减少错误，不代表视觉依据瓶颈已经解决。

## 5. 多数据、强基线、消融与完整证据

**输入：**方法、原型发现、拟议主张、已知失败边界和预算。

**操作：**每个实验回答明确主张及最强反解释。加入简单基线、最接近前作与相关强基线，匹配数据、划分、指标、骨干、训练/搜索预算；不可比公开分数单列。选择覆盖关键边界的独立数据/场景，检查共享对象、时间泄漏、近重复和同源数据。

开发选择与冻结后确认分开；消融说明固定其余部分还是重训/重调，测试有效替代和交互，不预设每个模块必要。报告实际重复次数、不确定性、统计假设、效应大小、成本、负结果和复现细节。[scikit-learn 文档](https://scikit-learn.org/stable/common_pitfalls.html)说明预处理与测试数据泄漏；[NeurIPS 检查表](https://neurips.cc/public/guides/PaperChecklist)可作特定领域的披露参考，但不是统一录用标准。

**产物：**验证协议或证据审计，每项主张都有结果出处、支持程度、局限和下一项决策。

**继续条件：**保留被支持范围内的主张；部分支持则缩小；不支持则修改或停止。不挑最好的 seed/数据集，也不默认辅助损失或分支能解决遗留问题。多数据集增强有限范围证据，不证明普遍泛化；某些组件完全可以被删掉。

**示例：**两个数据集共享 30% 图片，不是两次独立确认。用同一测试集挑 20 个配置之后，最佳提升属于开发选择证据，不能保持“未见测试”的名义。

## 6. 多线管理、资源限制与风险对冲

**输入：**已有方向、实际资源、截止期、依赖、证据和失败模式。

**操作：**需要时维护主线和成本可承受的备选。比较价值、下一项验证、成本、证据和共同风险；共用同一缺失数据或未经证实机制的方向，不自动构成独立对冲。决定优先、暂缓、修订或停止。

**产物：**简洁方向看板，含分配、备选维持成本、共同风险和切换/停止条件。

**切换条件：**核心预测被反证、所需数据长期不可得、收益不抵成本，或预算/期限触顶。短暂代码错误不等于方向失败。一条主线也可以，2–3 条不是配额。

本阶段贯穿全程，不是最后打卡。资源或证据变化时再复盘，不自动启动代理、多 GPU 任务、后台定时或无上限重试。

## 记录、断点继续与输出大小

优先使用现有笔记。简单诊断可以只给结论与下一项测试；完整项目可用模板保存问题定义、假说状态、文献支持、实验 ID、成本、负结果和决策。

断点继续时提供最近状态与新证据，让总入口更新判断，不默认从头重来。保存文件是持久上下文，不是自动续跑系统。

[项目状态模板](../locales/zh-CN/skills/research-closed-loop/assets/research-state.md)可以裁剪；留空或写未知，胜过填造假的数字。

## 能力边界

实证效果、机制解释、因果识别和外部有效性是不同主张，详见[判读边界](../locales/zh-CN/skills/research-closed-loop/references/decision-boundaries.md)。技能辅助推理，不替代数据、工具、统计、伦理和专业判断，也不保证发表、获奖、泛化或实验成功。
